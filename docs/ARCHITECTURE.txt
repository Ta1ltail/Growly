==========================================================
 GAMIFICATION MODEL  (the locked rule)
==========================================================
  ALL gamification - XP, levels, streaks, achievement progress,
  titles, ranks - is COMPUTED from the immutable mark history by
  pure functions in lib/. It is NEVER stored as a mutable counter.
  This keeps it consistent with Honest Tracking (anti-cheat): you
  cannot inflate progress without real marks, and the numbers can
  never desync from the record.

  The ONLY persisted gamification state (schema v3):
    - unlocks: { [achievementId]: { at, seen } }   (for one-time popups)
    - profile: editable identity (name, username, bio, motto,
               avatar, banner, showcaseBadgeId)

  One call does it all:
    summarizeProgress(data, today)
      -> { stats, achievements, unlockedCount, totalCount,
           xp, level, title, nextMilestones }
    (Note: it does NOT return `profile` - read data.profile directly.)

  reconcileUnlocks(data, today, nowIso) folds newly-satisfied
  achievements into the persisted unlock map (returns the SAME map
  reference when nothing changed, so callers skip the write).
  cycleMark() calls it on every mark; CelebrationManager renders the
  most-prestigious unseen unlock and marks it seen on dismiss.


==========================================================
 THEME SYSTEM
==========================================================
  - All colors are CSS variables (--c-*). Light values on :root,
    dark values on [data-theme="dark"]. Swap the attribute -> the
    whole app re-themes instantly. Accent is its own var (--c-accent).
  - layout.tsx runs a tiny inline script BEFORE paint that reads the
    saved theme from localStorage and applies it -> NO theme flash.
  - ThemeApplier (client) keeps it in sync and reacts to OS changes
    when mode = "system".
  - globals.css holds the full motion language: tokens (--animate-*,
    --ease-*, --dur-*) + every keyframe (flicker, glow-pulse, ember,
    burst, confetti-fall, toast-in, celebrate-in, spin-slow,
    text-sheen, float, ...). A global prefers-reduced-motion rule
    neutralizes animation for accessibility.


==========================================================
 DATA FLOW
==========================================================
  UI  ->  store actions (addHabit, cycleMark, updateProfile,
          markAchievementsSeen, ...)
       ->  update() writes localStorage + notifies subscribers
       ->  useAppData() (useSyncExternalStore) re-renders every
           screen. One source of truth.
  Derived gamification is recomputed on render via summarizeProgress
  (memoized per page) - nothing extra to persist or invalidate.

  memoization` requires useMemo deps to match the props actually
  read (use [data], not [data.marks, data.habits]). Render-phase
  setState (clamping a page, seeding a draft) is allowed; sync
  setState INSIDE an effect is not (react-hooks/set-state-in-effect).
