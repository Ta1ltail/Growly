==========================================================
 GAMIFICATION MODEL  (the locked rule)
==========================================================
  ALL gamification - XP, levels, streaks, achievement progress,
  titles, ranks, AND COINS - is COMPUTED from the immutable mark
  history by pure functions in lib/. It is NEVER stored as a mutable
  counter. This keeps it consistent with Honest Tracking (anti-cheat).

  The ONLY persisted gamification state (schema v6):
    - unlocks: { [achievementId]: { at, seen } }   (for one-time popups)
    - profile: editable identity
    - economy: spend ledger + owned/equipped cosmetics + freeze log +
               engagement fields (see ECONOMY MODEL below)

  One call does it all:
    summarizeProgress(data, today)
      -> { stats, achievements, unlockedCount, totalCount,
           xp, level, title, nextMilestones,
           coinsEarned, coinBalance }


==========================================================
 ECONOMY MODEL  (coins, shop, streak-freeze)
==========================================================
  Coins mirror XP: DERIVED, never granted. lib/economy.ts.
    balance = coinsEarned(history, unlockedRarities, economy)
           - SUM(spend ledger), clamped >= 0
    coinsEarned includes:
      - 2/completion + 10/perfect-day (from marks)
      - RARITY_COINS (from achievements)
      - bonusCoins (from engagement features - stored in economy)

  Persisted economy state (the ONLY mutable economy facts):
    - spent:       append-only { id, at, amount, item } ledger
    - owned:       cosmetic catalog ids bought
    - equipped:    { flame | confetti | accent -> itemId }
    - freezes:     dated streak-freeze log
    - bonusCoins:  cumulative engagement reward coins (v6)
    - lastCheckIn: dateKey of last daily check-in (v6)
    - checkInStreak: consecutive daily check-in count (v6)
    - lastQuestDate: dateKey of last quest generation (v6)
    - currentQuest: active DailyQuest (v6)
    - lastSpinDate: dateKey of last daily spin (v6)

  Engagement rewards are added to bonusCoins via store actions:
    claimDailyCheckIn() -> { reward, streak }
    refreshDailyQuest() / claimDailyQuest()
    doDailySpin() -> { label, amount, isFreeze }

  Streak-freeze: protects ONE genuine recorded miss. The miss stays
  in history; habitStreaks(..., frozen?) treats it as neutral.
    - Capped 1 per rolling 7 days
    - frozenSet() is threaded into all streak readouts + shown with
      snowflake badge (calendar day-detail + tracker grid)


==========================================================
 THEME SYSTEM
==========================================================
  - All colors are CSS variables (--c-*). Light on :root, dark on
    [data-theme="dark"]. Accent cosmetic overrides --c-accent.
  - layout.tsx inline script reads saved theme BEFORE paint -> NO flash.
  - globals.css holds the full motion language: tokens (--animate-*,
    --ease-*, --dur-*) + all keyframes. prefers-reduced-motion blanket.


==========================================================
 DATA FLOW
==========================================================
  UI  ->  store actions (addHabit, cycleMark, updateProfile,
          claimDailyCheckIn, ...)
       ->  update() writes localStorage + notifies subscribers
       ->  useAppData() (useSyncExternalStore) re-renders every
           screen. One source of truth.
  Derived gamification is recomputed on render via summarizeProgress.

  Keyboard shortcuts: useKeyboardShortcuts() in AppShell dispatches
    custom events (kb:toggle-help, kb:add-habit) and calls router.push
    for g-prefix navigation. Undo/redo via Ctrl+Z / Ctrl+Shift+Z
    calls store actions (undoAction / redoAction) backed by history.ts.

  Widget order + onboarding state persisted in settings via store actions
    (setWidgetOrder, completeOnboarding, addCustomCategory, ...).


==========================================================
 DEVELOPER MODE  (hidden power-user layer)
==========================================================
  Unlocked with Ctrl/Cmd+Shift+D -> FAB -> slide-over. Own localStorage
  store (lib/devmode.ts, key project101.devmode.v1). 8 sections,
  cross-section search, data tools (JSON edit, export/import, seed,
  wipe). Derived-gamification invariant still holds: dev tools only
  edit persisted facts; coins/XP/streaks recompute from history.
