==========================================================
 GAMIFICATION MODEL  (the locked rule)
==========================================================
  ALL gamification - XP, levels, streaks, achievement progress,
  titles, ranks, AND COINS - is COMPUTED from the immutable mark
  history by pure functions in lib/. It is NEVER stored as a mutable
  counter. This keeps it consistent with Honest Tracking (anti-cheat):
  you cannot inflate progress without real marks, and the numbers can
  never desync from the record.

  The ONLY persisted gamification state (schema v4):
    - unlocks: { [achievementId]: { at, seen } }   (for one-time popups)
    - profile: editable identity (name, username, bio, motto,
               avatar, banner, showcaseBadgeId)
    - economy: append-only spend ledger + owned/equipped cosmetics +
               dated streak-freeze log (see ECONOMY MODEL below)

  One call does it all:
    summarizeProgress(data, today)
      -> { stats, achievements, unlockedCount, totalCount,
           xp, level, title, nextMilestones,
           coinsEarned, coinBalance }
    (Note: it does NOT return `profile` - read data.profile directly.)

  reconcileUnlocks(data, today, nowIso) folds newly-satisfied
  achievements into the persisted unlock map (returns the SAME map
  reference when nothing changed, so callers skip the write).
  cycleMark() calls it on every mark; CelebrationManager renders the
  most-prestigious unseen unlock and marks it seen on dismiss.


==========================================================
 ECONOMY MODEL  (coins, shop, streak-freeze)
==========================================================
  Coins mirror XP: DERIVED, never granted. lib/economy.ts.
    balance = coinsEarned(history) - SUM(spend ledger), clamped >= 0
    coinsEarned = 2/completion + 10/perfect-day + rarity achievement
                  bonuses (RARITY_COINS). coinBreakdown() itemizes it
                  for the /shop "where your coins come from" card.

  Persisted economy state (the ONLY mutable economy facts):
    - spent:    append-only { id, at, amount, item } ledger
    - owned:    cosmetic catalog ids bought
    - equipped: { flame | confetti | accent -> itemId }
    - freezes:  dated streak-freeze log { id, at, date, habitId }

  Cosmetics (3 slots, free "default" per slot, some level-gated):
    - flame    -> FLAME_SKINS recolor StreakFlame's tier ramp
    - confetti -> CONFETTI_SKINS recolor AchievementCelebration
    - accent   -> ACCENT_SKINS; AccentThemeApplier overrides
                  --c-accent/--c-accent-glow on <html> app-wide
                  (default clears the override -> themed accent)
    equippedOrDefault(economy, slot) resolves the active id.

  Streak-freeze (logged, limited consumable, FREEZE_PRICE coins):
    - protects ONE genuine recorded miss (status "missed") - the miss
      STAYS in history; habitStreaks(..., frozen?) just treats that
      habitId@dateKey as neutral. Honest Tracking holds.
    - capped 1 per rolling 7 days (canUseFreeze); only past misses are
      eligible (freezableDays / canFreezeDay).
    - frozen days show a snowflake badge in the calendar day-detail and
      the tracker grid (MarkButton `frozen` prop / cell overlay).
    - frozenSet(economy) is threaded into buildGameStats AND every UI
      streak readout (today/dashboard/habits/tracker/stats) so the
      protection is consistent everywhere.

  store actions: buyCosmetic, equipCosmetic, redeemFreeze (NB: not
  "useFreeze" - the use* prefix trips eslint rules-of-hooks).


==========================================================
 THEME SYSTEM
==========================================================
  - All colors are CSS variables (--c-*). Light values on :root,
    dark values on [data-theme="dark"]. Swap the attribute -> the
    whole app re-themes instantly. Accent is its own var (--c-accent);
    an equipped "accent" cosmetic overrides it via AccentThemeApplier
    (inline style on <html>), the default clears the override.
  - layout.tsx runs a tiny inline script BEFORE paint that reads the
    saved theme from localStorage and applies it -> NO theme flash.
  - ThemeApplier (client) keeps it in sync and reacts to OS changes
    when mode = "system".
  - globals.css holds the full motion language: tokens (--animate-*,
    --ease-*, --dur-*) + every keyframe (flicker, glow-pulse, ember,
    burst, confetti-fall, toast-in, celebrate-in, spin-slow,
    text-sheen, float, ...). A global prefers-reduced-motion rule
    neutralizes animation for accessibility.


==========================================================
 DATA FLOW
==========================================================
  UI  ->  store actions (addHabit, cycleMark, updateProfile,
          markAchievementsSeen, ...)
       ->  update() writes localStorage + notifies subscribers
       ->  useAppData() (useSyncExternalStore) re-renders every
           screen. One source of truth.
  Derived gamification is recomputed on render via summarizeProgress
  (memoized per page) - nothing extra to persist or invalidate.

  read (use [data], not [data.marks, data.habits]). Render-phase
  setState (clamping a page, seeding a draft) is allowed; sync
  setState INSIDE an effect is not (react-hooks/set-state-in-effect).
  Hook-name gotcha: a plain helper must NOT start with `use` if it's
  called from a non-component/non-hook fn (rules-of-hooks).


==========================================================
 DEVELOPER MODE  (hidden power-user layer)
==========================================================
  A hidden advanced-settings popup, separate from user Settings.
  Unlocked (and persisted) with Ctrl/Cmd+Shift+D -> a bottom-right FAB
  opens a right-side slide-over. Mounted once via <DevMode/> in AppShell.

  Settings live in their OWN store (lib/devmode.ts, key
  project101.devmode.v1) so they can never corrupt or migrate with the
  schema-v4 app data. Data tools act on the real store through
  replaceData / reloadData / importRawData (store.ts).

  Sections: General, UI Controls (theme + debug overlays via an injected
  <style>), Performance (FPS meter, footprint, stress seed), Database
  Tools (raw JSON edit/apply, export/import, seed demo, wipe slices),
  User Controls (live profile edit, grace window, force-unlock/relock
  achievements), AI Settings (INERT - no AI backend; persisted prototype
  surface only), Debug Tools (trigger celebration, log state, throw test
  error, nuke storage), System Information. A search box filters rows
  across every section (matchQuery on label/hint/terms).

  Derived-gamification invariant still holds: dev tools only edit the
  PERSISTED facts (marks, unlocks, profile, economy ledger); coins/XP/
  streaks recompute from history as always.
