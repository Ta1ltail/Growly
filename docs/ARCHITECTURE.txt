==========================================================
 GAMIFICATION MODEL
==========================================================
  ALL gamification (XP, levels, streaks, achievement progress,
  titles, ranks, coins) is COMPUTED from the immutable mark
  history by pure functions. NEVER stored as a mutable counter.

  The ONLY persisted gamification state:
    - unlocks: { [achievementId]: { at, seen } }
    - profile: editable identity
    - economy: spend ledger + owned/equipped cosmetics + freeze log +
               engagement fields

  One call:
    summarizeProgress(data, today)
      -> { stats, achievements, unlockedCount, totalCount,
           xp, level, title, nextMilestones, coinsEarned, coinBalance }


==========================================================
 ECONOMY MODEL
==========================================================
  Coins mirror XP: DERIVED, never granted.
    balance = coinsEarned(history, unlockedRarities, economy)
           - SUM(spend ledger), clamped >= 0

  Persisted economy state:
    - spent       append-only spend ledger
    - owned       cosmetic catalog ids bought
    - equipped    { flame | confetti | accent -> itemId }
    - freezes     dated streak-freeze log
    - bonusCoins  cumulative engagement reward coins
    - lastCheckIn / checkInStreak / lastQuestDate / currentQuest
    - lastSpinDate


==========================================================
 THEME SYSTEM
==========================================================
  - CSS variables (--c-*). Light on :root, dark on [data-theme="dark"].
    Accent cosmetics override --c-accent.
  - layout.tsx inline script reads saved theme BEFORE paint -> no flash.
  - globals.css holds the full motion language + keyframes.
  - prefers-reduced-motion disables animations.


==========================================================
 DATA FLOW
==========================================================
  UI -> store actions (addHabit, cycleMark, ...)
     -> update() writes localStorage + notifies subscribers
     -> useAppData() (useSyncExternalStore) re-renders subscribers.

  Sync (when authenticated):
    Store mutation -> pushMutation(supabase, userId, data, changed)
    On mount/refresh -> pullAllUserData(userId) replaces localStorage

  Performance:
    - Debounced saves (100ms) for high-frequency mark toggles
    - React.memo on 11 components
    - useMemo on expensive computations
    - Lazy-loaded Confetti (React.lazy + Suspense)
    - useAppDataSelector for granular subscriptions

==========================================================
 DATABASE PERFORMANCE
==========================================================
  Indexes (migrations 001-012):
  - All user_id columns indexed on every table
  - Composite: friends(requester,status), friends(addressee,status)
  - Sort: notifications(created_at DESC), suggestions(created_at DESC)
  - Lookup: user_profile(username) for public profile queries
  - Leaderboard: 4 covering indexes on user_stats_snapshots
    (level DESC, current_streak DESC, consistency_14d DESC,
     total_completions DESC) each INCLUDE-ing all display columns
    for index-only scans.

  Server-side pagination:
  - Leaderboard: .order().range() with count:'exact' (20 rows/page)
  - Friends: pending/accepted split, .range() for accepted list

  Daily cron (migration 010):
  - refresh_stale_snapshots() PostgreSQL function recalculates stats
  - Recursive CTE for current streak, gaps-and-islands for best streak
  - Schedule: daily at 03:00 UTC via pg_cron

  Monitoring (migration 012):
  - pg_stat_statements extension enabled
  - Query: SELECT query, calls, mean_exec_time, rows
           FROM extensions.pg_stat_statements ORDER BY mean_exec_time DESC LIMIT 20

==========================================================
 KNOWN LIMITATIONS
==========================================================
  - Turbopack crashes on Windows (uses --webpack dev flag)
  - postcss vulnerability in next@16.2.9 transitive dep
  - Auth is email/password only (sessions managed via Supabase cookies)
  - No social OAuth (Google, GitHub) — planned
  - Cloud sync is functional but localStorage-first (no conflict resolution)
  - pg_cron extension required for daily stats refresh (enabled by default in Supabase)
